二、 针对您提到“0.25° (27km) 局地偏差”的补充技术评估
您指出的 ECMWF IFS 0.1° (~9km) 与 GFS/AIFS 0.25° (~27km) 网格的局地偏差问题极其致命：

高程平滑塌陷（Topography Smoothing）
在 27 km × 27 km（IFS 0.1° 为 9 km × 9 km）的单一网格内，模型提取的平均高程可能只有 5000 米左右。这意味着全球数值模型把“珠峰顶峰（8848m）”在数学上抹平成了五六千米的高原！如果不做高程插值与风场局地降尺度（Downscaling），取出来的风速和温度用于 C4 (7900m) 或峰顶就是杀人依据。

垂直等压层（Pressure Levels）的不可替代性
审计气象源时，必须审查其是否开放高空等压层数据（如 500hPa 对应 ~5500m，300hPa 对应 ~9100m）。必须通过多等压层物理插值计算气象变量，决不能直接读取 Surface（地表）变量。

三、 核心架构纠偏与避坑指南摆脱 SaaS 流量陷阱 (Cesium Ion)：工程决策：生产环境严禁直接依赖 Cesium Ion SaaS API。实施方案：采用 Copernicus DEM GLO-30 + cesium-terrain-builder 自行切片为 Quantized-Mesh 静态高程瓦片，配合 Nginx / AWS S3 CDN 提供分发，使运营成本降低 90% 以上。实测站离线降级机制 (Everest AWS)：工程决策：Everest AWS 是极佳的 Ground Truth 锚点，但硬件极易因暴风雪失效。实施方案：系统需内置传感器失效退阶算法。当 South Col 等站点超过 45 分钟无数据回传时，系统自动降级至 ECMWF IFS 的高空 300hPa/400hPa 等压层垂直插值模型，并向界面提示“实测站数据离线，已启用高空数值模型”。纠正遥感数据物理理解误区 (Sentinel-1 SAR)：工程决策：Sentinel-1 InSAR 无法“穿透山体/洞穴”，仅用于厘米级地表形变测量。实施方案：Sentinel-1 不参与实时气象/风险计算，仅作为后台离线任务，每月运行一次，计算昆布冰川整体流速与沉降趋势。合规使用开源数据 (OpenStreetMap ODbL)：工程决策：离线提取 Geofabrik 尼泊尔 PBF 矢量，提取直升机停机坪 (helipad) 及山谷路径 (path)。实施方案：前端界面需保留 © OpenStreetMap contributors 版权署名，且保持矢量数据层独立，避免与私有商业算法数据发生 ODbL 协议污染。

1. 后端卡尔曼滤波风速校准算法伪代码（⚠️ Phase 2 预留参考：属 Risk/实测站模块，超出当前 A-F 交付边界，当前不实现）高海拔复杂地形（如珠峰大本营至峰顶区域）的传感器易受强风阵风及地形风效应干扰。算法基于一维扩展卡尔曼滤波（EKF），状态向量设定为 $x = [v, \dot{v}]^T$（风速及其加速度），并结合高程地形粗糙度因子 $z$ 进行观测更新。Python# 核心算法逻辑：卡尔曼滤波风速与高程 Roughness 校准
class WindKalmanFilter:
    function __init__(dt, Q_cov, R_cov):
        self.dt = dt                 # 采样间隔 (秒)
        self.x = Vector2D(0.0, 0.0)  # 状态量: [风速(m/s), 风加速度(m/s^2)]
        self.P = Matrix2x2.identity() * 1.0  # 状态协方差阵
        
        # 状态转移矩阵 F (x_k = F * x_{k-1})
        self.F = Matrix2x2(1.0, dt, 0.0, 1.0)
        # 观测矩阵 H (观测值为传感器读出的风速)
        self.H = Matrix1x2(1.0, 0.0)
        
        self.Q = Q_cov   # 过程噪声协方差 (描述风速突变的随机性)
        self.R_base = R_cov # 基础观测噪声协方差 (传感器物理误差)

    function predict():
        # 1. 状态预测: x_k|k-1 = F * x_{k-1|k-1}
        self.x = self.F * self.x
        # 2. 协方差预测: P_k|k-1 = F * P_{k-1|k-1} * F^T + Q
        self.P = (self.F * self.P * self.F.transpose()) + self.Q
        return self.x[0]

    function update(z_measured, terrain_roughness, elevation):
        # 根据海拔及地形粗糙度动态调整观测噪声 R
        # 高海拔陡峭地形粗糙度大，传感器振动高噪，需加大 R 以信任预测值
        alpha = 1.0 + (elevation / 8848.0) * terrain_roughness
        R_dynamic = self.R_base * alpha

        # 1. 计算测量残差 y = z - H * x
        y = z_measured - (self.H * self.x)
        # 2. 计算残差协方差 S = H * P * H^T + R
        S = (self.H * self.P * self.H.transpose()) + R_dynamic
        # 3. 计算卡尔曼增益 K = P * H^T * S^-1
        K = self.P * self.H.transpose() * (1.0 / S)
        
        # 4. 状态更新 x = x + K * y
        self.x = self.x + (K * y)
        # 5. 协方差更新 P = (I - K * H) * P
        I = Matrix2x2.identity()
        self.P = (I - (K * self.H)) * self.P
        
        return self.x[0] # 返回校准后的稳定风速 (m/s)

1) PostGIS 自定义粗糙度提取函数 (extract_roughness.sql)
SQL
-- 传入站点经纬度，从 DEM 栅格中提取 3x3 邻域高程标准差作为粗糙度因子 (Roughness Factor)
CREATE OR REPLACE FUNCTION get_terrain_roughness(lon NUMERIC, lat NUMERIC)
RETURNS NUMERIC AS $$
DECLARE
    point_geom GEOMETRY;
    roughness NUMERIC;
BEGIN
    point_geom := ST_SetSRID(ST_MakePoint(lon, lat), 4326);
    
    -- 计算指定坐标周围 DEM 栅格值的标准差 (ST_SummaryStats)
    SELECT COALESCE(ST_StdDev(ST_Clip(rast, ST_Buffer(point_geom, 0.005))), 1.0)
    INTO roughness
    FROM terrain_dem
    WHERE ST_Intersects(rast, point_geom)
    LIMIT 1;

    -- 归一化粗糙度范围 [1.0, 3.0]
    RETURN LEAST(GREATEST(roughness / 10.0, 1.0), 3.0);
END;
$$ LANGUAGE plpgsql;

	TrippedAt    time.Time `json:"tripped_at"`   // 触发时间

// EvaluateRisk 评估 South Col 及高海拔风速
func EvaluateRisk(event WindEvent) {
	breaker.mu.Lock()
	defer breaker.mu.Unlock()

	// 换算: 50 km/h ≈ 13.89 m/s (大风/强阵风门槛)
	// Balcony/死区以上 (Elevation >= 8000m) 阵风 > 13.89 m/s 立即触发最高级别安全熔断
	if event.Elevation >= 8000.0 && event.CalibratedSpeed >= 13.89 {
		breaker.IsTripped = true
		breaker.TrippedAt = time.Now()
		breaker.RiskLevel = "CRITICAL"
		breaker.TriggerReason = fmt.Sprintf("Balcony 以上 (海拔 %.0fm) 监测到极端风速 %.2f m/s (%.1f km/h)，已触发强制避险", 
			event.Elevation, event.CalibratedSpeed, event.CalibratedSpeed*3.6)
	} else if event.CalibratedSpeed >= 10.0 {
		breaker.RiskLevel = "WARNING"
		breaker.TriggerReason = "高海拔阵风加大，建议暂停 C3-C4 冲顶规划"
	} else {
		if time.Since(breaker.TrippedAt) > 30*time.Minute {
			breaker.IsTripped = false
			breaker.RiskLevel = "NORMAL"
			breaker.TriggerReason = "风速回落至安全区间"
		}
	}
}

3.2 WebGL / Canvas 动态风速粒子与热力叠加
离屏 Canvas 渲染：利用后端返回的卡尔曼校准点阵，在 1024x1024 离屏 Canvas 上动态绘制径向渐变热力图（绿色 <15m/s，黄色 15∼25m/s，红色 >25m/s）。

地形贴合与 60FPS 优化：使用 Cesium.SingleTileImageryProvider 将热力 Canvas 实时贴合至 3D 山体表面，通过 RequestAnimationFrame 维持 45+ FPS 流畅渲染。

模块四：极端环境安全断路器（Safety Circuit Breaker）
用硬编码与极轻量的高并发服务，防止恶劣天气导致的人员误判。

4.1 熔断触发条件与阈值设定
在海拔 ≥8000m（死区/Balcony 以上），系统设立硬性断路指标：

指标维度	正常 (Normal)	警告 (Warning)	强制熔断 (Critical / Tripped)
Balcony 以上/冲顶风速	<10m/s (≈36km/h)	10∼13.89m/s	≥13.89m/s (≥50km/h 阵风)
实测站离线时间	<15min	15∼45min	>45min（强制自动降级至高空模型）
系统响应行为	路线显示绿色通行	路线高亮黄色警示	3D 地图锁定路线红色闪烁，抛出 Block 指令
4.2 Go 语言高并发断路器服务实现
毫秒级状态机：利用 Go 的 sync.RWMutex 读写锁维护全局 CircuitBreaker 结构体。

自动冷却恢复机制：一旦触发熔断，系统进入强制锁定时长（如 30 分钟）。只有当最新风速持续低于安全门槛且维持 30 分钟以上，熔断器才会解除。

API 接口：暴露 /api/v1/breaker/status 端口，供前端 Cesium UI 与山下救援指挥部客户端毫秒级轮询。
